# vulnfeed

Трекер CVE и вендорских EOL/анонсов. Вынесен из дашборда «Тенге и аптайм»:
там был снимок, который перезаписывался целиком, здесь — база с историей
состояний.

Работает без сервера: GitHub Actions собирает по расписанию, SQLite лежит
файлом в репозитории, статика раздаётся с GitHub Pages.

## Что уже работает

- `sources/kev.py` — CISA KEV: один JSON, без ключей и пагинации.
- `sources/nvd.py` — NVD API 2.0: оценки CVSS, пагинация, пауза между
  страницами, приоритет метрик v4.0 → v3.1 → v3.0 → v2.
- `db.py` — upsert с историей: изменение отслеживаемого поля пишется
  в `cve_event`. Это ядро, на нём тесты.
- `render.py` + `templates/` — генерация `docs/index.html`, светлая и тёмная тема.
- `.github/workflows/collect.yml` — прогон по крону, тесты перед сбором,
  коммит только при реальном изменении.

## Запуск локально

```bash
uv sync --all-extras
uv run pytest -q

# без сети, на фикстурах
uv run vulnfeed-collect --kev-fixture tests/fixtures/kev_sample.json --skip-nvd
uv run vulnfeed-render
open docs/index.html
```

Боевой прогон (нужна сеть):

```bash
export NVD_API_KEY=...        # необязательно, но без него медленно
uv run vulnfeed-collect
uv run vulnfeed-render
```

## Логика отбора

Из `config.toml`: `min_cvss = 8.6`, окно 60 дней. Запись из KEV проходит
мимо порога — подтверждённая эксплуатация важнее оценки. Вендоры и строки
поиска там же, правятся без кода.

## Что осталось сделать

1. **Вендорские ленты.** Таблица `vendor_item` и рендер готовы, источников нет.
   Порядок по убыванию простоты: форум MikroTik и `blog.ui.com` отдают RSS,
   TP-Link — парсинг темы на форуме, RUCKUS — бюллетени за логином,
   Dahua — 403 и закрыто в robots.txt. Последние два автоматом не берутся:
   либо руками, либо через LLM-проход, который пишет в ту же базу.
2. **Pages.** Settings → Pages → Source: Deploy from a branch, папка `/docs`.
   Из приватного репозитория Pages требует платный план — проверь под свой
   аккаунт до того, как закладываться на приватность.
3. **Keepalive.** Scheduled workflow отключается после 60 дней неактивности
   репозитория, и коммит бота счётчик сбрасывает не всегда. Либо ставь
   keepalive-экшен, либо раз в пару месяцев коммить руками. Иначе трекер
   тихо умрёт, и ты узнаешь об этом позже, чем хотелось бы.
4. **Порог для Cisco/Fortinet/Zyxel/SonicWall.** У них поток CVE большой,
   `keywordSearch` даёт много лишнего. Либо сузить ключевые слова до
   конкретных линеек, либо перевести эти вендоры на «только KEV»
   (пустой `nvd_keyword`).

## Оговорки

- `tests/fixtures/*.json` — усечённые образцы структуры KEV для тестов,
  а не актуальный каталог. Записи в них реальные (SonicWall, Cisco, Dahua
  подтверждались по публикациям), но набор собран под проверку логики:
  дедупликацию, историю изменений и фильтр вендоров.
- Секретов в репозитории нет: `NVD_API_KEY` берётся из окружения, в Actions —
  из Secrets. Ничего не хардкодить.
- Правки в `docs/index.html` руками бессмысленны: файл собирается заново
  каждым прогоном.
